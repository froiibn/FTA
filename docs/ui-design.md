# 데스크톱 UI 설계

작성일: 2026-10-25. TypeScript·Tauri 공통 화면의 디자인 및 동작 기준이다.

## 방향과 사전 검토

대상은 집 안의 네 컴퓨터에 파일·텍스트·링크를 보내는 개인용 전송 유틸리티다. 홍보 페이지가 아니라 자주 열고 닫는 작은 작업 창으로 설계한다. 첫 시선에서 받는 기기, 선택한 파일, 전송 동작을 구분할 수 있어야 한다.

초기 화면의 큰 브랜드 아이콘, 가운데 정렬 안내, 연녹색 카드, 슬로건 푸터는 실제 전송과 관련 없는 면적을 차지해 제거한다. 정보는 좌측 정렬하고 네이티브 파일 관리 도구처럼 목록·툴바·상태를 이용해 구조화한다. 색상의 강한 사용은 선택한 목적지와 주 전송 동작에 한정한다.

## 디자인 토큰

| 토큰 | 값 | 역할 |
|---|---|---|
| surface | `#F3F5F7` | 창 바탕·툴바 |
| paper | `#FFFFFF` | 작업 영역·입력 |
| ink | `#1F2937` | 제목·본문 |
| navy | `#24466B` | 선택·주 동작 |
| line | `#D8DEE6` | 영역·목록 구분 |
| status | `#367652` | 실제 연결·완료 상태 |

글꼴은 `-apple-system`, `BlinkMacSystemFont`, `Apple SD Gothic Neo`, `Segoe UI`, `Malgun Gothic`, `sans-serif` 순으로 사용한다. 외부 CDN이나 폰트 다운로드 없이 오프라인에서 동작한다. 기본 본문은 13px, 보조 정보는 12px, 구역 제목은 14px, 앱 이름은 18px다. 데이터 크기와 진행 수치는 tabular numerals를 사용한다.

버튼·입력은 5px, 창 내부 구역은 7px 정도의 작은 곡률로 계층을 구분한다. 그림자·그라데이션·자동 등장 애니메이션은 사용하지 않는다. 구분선은 기능 영역과 목록 경계를 표시할 때만 사용한다.

작은 창에서는 하나의 열을 사용하고 760px 이상에서는 목적지 목록을 고정 폭의 왼쪽 레일로 이동한다. 레일이 비어 있어도 예시 기기를 만들지 않고 등록 안내를 제공한다. 설정은 기기·네트워크, 앱 동작, 기기 등록으로 구분하며 큰 창에서는 관련 입력을 두 열에 놓는다.

## 상호작용과 접근성

- 기기 선택은 이름·OS·텍스트 상태·선택 표시를 함께 사용한다. 색상만으로 온라인·선택 상태를 전달하지 않는다.
- 모든 동작은 키보드 Tab으로 접근하고 focus-visible을 명확하게 표시한다. 설정·기기 등록으로 이동할 때 포커스도 따라간다.
- 파일·메시지 전송의 목적지를 항상 표시한다. 오프라인 또는 미등록 기기는 전송 대상으로 선택할 수 없다.
- 진행률은 엔진에서 제공한 실제 바이트 수로 계산한다. 값이 아직 없으면 준비 중 상태를 보여주고 임의 퍼센트를 넣지 않는다.
- 내용과 오류는 textContent로 표시한다. 알림 클릭은 전송 ID로 저장 기록을 조회한다.
- 브라우저 미리보기에는 연결·기기·기록을 꾸며 넣지 않고 네이티브 앱이 필요함을 표시한다.
- 재설계 후 기본 빈 화면, 연결 오류, 설정 화면, 480px·넓은 화면, 키보드 포커스, 내용이 긴 목록을 실제 렌더링으로 확인한다.

## 검증 기록

2026-10-25에 TypeScript 엄격 타입 검사·프로덕션 빌드가 통과했다. Playwright 실제 브라우저에서 480×760 단일 열, 1000×800 목적지 레일, 설정의 두 열 배치를 렌더링하고 스크린샷을 육안 검토했다. 작업 창의 목적지·전송 동작이 먼저 읽히고, 슬로건·카드 그림자·장식용 배지가 없는지 확인했다. 검증 산출물은 `output/playwright/ui-widget.png`, `ui-wide.png`, `ui-settings.png`다.

네이티브 알림·드롭·자동 실행은 브라우저 검증으로 완료했다고 판단하지 않는다. 앱 번들 생성과 delegate 컴파일은 완료했지만, 실제 OS의 허용·거부·집중 모드·앱 종료 후 클릭은 별도 실기 검증 항목이다.

## 작은 창 개편 (2026-10-25)

사용자 피드백에 따라 기본 창을 380×560 논리 픽셀, 최소 340×480으로 줄인다. 기존 색상·OS 글꼴·13px 본문은 유지하고 헤더·탭·영역 여백·드롭 높이·입력 높이를 줄인다. 글자나 화면 전체를 비율 축소하는 방식은 사용하지 않는다. 작은 창에서는 기기 목록 자체가 목적지를 표시하므로 중복된 목적지 행을 숨기고 긴 목록은 내부 스크롤로 제한한다. 설정·기록은 페이지 스크롤을 허용한다.

계획 검토: 종전 창의 큰 면적은 드롭 영역·여백·중복 목적지 행에서 발생했다. 이 부분을 줄여 실제 전송 조작에 공간을 배분하며 폰트 축소와 장식 변경은 피한다. 저장된 큰 창 크기를 강제로 초기화하지 않고 ‘작게’ 버튼으로 설정 파일의 기본 크기에 복귀한다. 넓은 창 레이아웃·드롭·파일 선택·텍스트 전송 동작은 유지한다. 검증은 380×560, 최소 340×480, 넓은 창에서 실시한다.

검증: macOS에서 데스크톱 check·테스트 5개·Clippy와 TypeScript/Vite 빌드 통과. 브라우저에서 380×560 전체 기본 조작 영역, 340×480 세로 스크롤, 1000×800 넓은 레이아웃과 설정 탭을 확인했다. Windows 네이티브 DPI 및 ‘작게’ 명령의 실제 창 크기 변경은 아직 실기 미검증이다.

## 정사각형 개편 (2026-10-25)

기본 400×400, 최소 340×340 논리 픽셀로 변경한다. 기존 색상·OS 글꼴은 유지한다. 툴바·한 줄 연결 상태·탭 아래 기기 목록, 파일 놓기, 텍스트 입력·보내기만 둔다. 중복 목적지·제목·파일 형식·승인 안내·등록 설명은 마크업과 갱신 코드에서 제거한다. 아이콘은 접근성 이름과 툴팁을 제공한다. 실제 오류·연결 상태·설정 필드명은 유지한다.

사전 검토: 높이만 줄이면 스크롤만 늘어나므로 반복 문구를 제거하고 툴바와 입력 높이를 줄인다. 긴 목록·설정은 스크롤을 허용하며 글자 크기와 창 확장 기능은 유지한다.

검증: 400×400 기본 화면에서 필수 조작이 한 화면에 배치되는 것을 확인했다. 최소 340×340에서는 세로 스크롤로 접근하며 설정 탭 이동도 확인했다. TypeScript/Vite 빌드, macOS 데스크톱 cargo check, 포맷·diff 검사를 통과했다. Windows 네이티브 배율·실제 창 변경은 미검증이다.

## 가로 기기 선택 (2026-10-25)

기기 선택은 컴퓨터 아이콘 아래 이름만 표시하는 가로 목록으로 변경한다. 네이비·OS 글꼴·기존 기본 창 크기는 유지한다. 여러 기기는 같은 줄에 나열하고 폭을 넘으면 가로 스크롤한다. 검토: OS·온라인 텍스트 열과 체크 표식을 제거하고 선택은 테두리·배경으로 표시한다. 오프라인·미등록 상태는 비활성화 및 툴팁·접근성 이름으로 구분한다. 긴 이름은 말줄임하고 전체 이름을 툴팁에 제공한다. 임의 예시 기기를 실제 목록에 추가하지 않는다.

검증: TypeScript/Vite 및 macOS 앱 번들 빌드 통과. 실제 네이티브 앱에서 등록된 Windows 기기의 아이콘·이름 표시와 선택 테두리·전송 대상 반영을 확인했다. 여러 실제 기기는 추가 등록하지 않았으며 가로 배열·스크롤은 CSS 구성으로 확인했다.

## 기기 아이콘 직접 드롭 (2026-10-25)

별도 파일 놓기 영역을 제거한다. 드래그 중 온라인 등록 기기 타일만 강조하고, 놓은 좌표에 있는 기기로 즉시 전송한다. 이전에 선택한 기기나 창의 다른 영역으로 전송 대상을 추정하지 않는다. 파일 선택은 작은 버튼으로 유지한다. 검토: 네이티브 물리 좌표를 DPI에 맞는 논리 좌표로 변환하고 놓은 시점에 타일·온라인·등록 상태를 재검증한다. 바깥 드롭·전송 중 드롭은 전송하지 않는다.

검증: macOS 데스크톱 check·기존 테스트 5개·Clippy, TypeScript/Vite 및 앱 번들 빌드 통과. 실제 앱에서 별도 드롭 영역 제거와 파일 선택 버튼 유지를 확인했다. Finder/Explorer의 실제 드래그 좌표·아이콘 바깥 거부·OS별 DPI 경계는 아직 실기 미검증이다. 앞선 CLI LAN 시험을 UI 드롭 통과로 대체하지 않는다.

## 상태 점과 기록·설정 팝업 (2026-10-25)

My computer 연결 구역과 탭을 제거한다. 기기 아이콘 오른쪽 아래 초록(온라인), 회색(오프라인), 주황(등록 필요) 점을 표시하고 접근성 이름·툴팁에도 상태를 유지한다. 상단에는 기록·설정·새로고침 아이콘을 배치한다. 기록과 설정은 각각 이름·닫기 버튼을 갖는 별도 모달 팝업으로 열어 기본 전송 화면을 유지한다. Escape와 닫기 후 초점을 복귀하고 설정·기록의 긴 내용은 팝업 내부에서 스크롤한다. 검토: 상태 구역 제거로 오류까지 사라지지 않도록 실제 연결 실패는 알림 영역으로 전달하고 팝업 작업 오류도 현재 열린 팝업에 표시한다. 팝업을 연 동안 배경 기기로 드롭하지 않는다.

검증: TypeScript/Vite와 macOS 앱 번들 빌드 통과. 실제 네이티브 앱에서 My computer·탭 제거, 등록된 온라인 Windows 기기의 초록 점, 기록 팝업의 실제 전송 내역·닫기, 설정 팝업의 실제 값·내부 스크롤·Escape 복귀를 확인했다. 설정 변경·기록 삭제는 실행하지 않았다. 오프라인·미등록 실기 상태 점은 추가 검증 범위다.

## 고정 다크 테마·독립 도구 창 (2026-10-25)

계획: 본체는 320×300(최소 280×260) 전송 위젯으로 줄인다. 배경 `#171B20`, 작업면 `#1E242B`, 본문 `#E3E9EF`, 보조 `#9BA9B8`, 경계 `#343D48`, 강조 `#88ADD2`, 온라인 `#76BD96`을 고정 사용한다. 테마 전환 기능은 제공하지 않는다. OS 글꼴 13px 본문은 유지하고 툴바·가로 기기 아이콘·텍스트 입력만 본체에 남긴다. 입력 오른쪽 아래 내부의 화살표가 보내기이며 접근성 이름과 툴팁을 갖는다.

레이아웃: 본체의 기록·설정 아이콘은 실제 독립 OS 창을 열고 기존 창이 있으면 재사용한다. 기록 600×520, 설정 520×640으로 본체와 크기·위치를 분리한다. 내부 모달은 기록 상세 보기에서만 사용한다. 새 창은 자기 역할의 콘텐츠만 생성하고 수신 알림 커서·알림 제출·활성화 소비·엔진 시작은 본체만 담당한다.

사전 검토: 단순 CSS 다크 반전이나 어두운 랜딩 페이지가 아니라 빈번한 개인 전송을 위한 작은 도구 창으로 맞춘다. 큰 제목·테마 토글·별도 보내기 행을 추가하지 않는다. 색상만으로 기기 상태를 전달하지 않도록 기존 툴팁과 접근성 상태는 유지한다. 설정/기록의 내용은 독립 창에서 충분한 공간과 내부 스크롤을 제공한다.

이번 개편 실기 검증: macOS에서 기본 크기320×300 본체, 다크 네이티브 제목 표시줄·콘텐츠, 입력 영역 안 화살표를 확인했다. 설정520×640·기록600×520이 각각 다른 OS 창으로 실제 열리고 실제 설정·전송 내역을 표시했다. 설정 내부 닫기·기록 OS 닫기는 해당 창만 닫고 본체와 독립 엔진을 유지했다. 입력 시 화살표 활성화·비우면 비활성화를 확인했고 메시지는 보내지 않았다. 데스크톱7개 테스트·check·Clippy·fmt, TypeScript/Vite·앱 번들 빌드 통과. Windows 다중 창과 UI 드롭은 실기 미검증이다.

## 자체 타이틀바와 접기 (2026-10-25)

OS 기본 타이틀바를 제거하고 앱과 같은 다크색의 자체 헤더를 사용한다. 본체는 280×260 기본 크기로 축소하고 헤더의 빈 영역을 드래그해 이동한다. 설정은 톱니바퀴 아이콘으로 표시한다. 기존 작은 창 크기 복귀 버튼은 제거하고 마이너스 접기 버튼으로 대체한다. 접으면 본체 DOM·입력·선택·알림 처리는 유지한 채 44×44 펼치기 버튼 하나만 보인다. 펼쳐 기기 타일에 파일을 드롭한다.
