# 화면·조작 상세 설계

작성일: 2026-10-25. Windows·macOS 공통 흐름과 Linux 명령어 계약의 기준안이다.

## 1. 최초 실행

`기기 이름 확인 → 수신 폴더 지정 → 집 네트워크 선택 → OS 권한 안내 → 자동 실행 선택 → 감지된 기기로 전송 → 상대에서 최초 등록 확인`

알림 권한은 수신 승인과 별개인 OS 설정이다. 알림을 거부해도 전송은 허용한다. 네트워크 권한이나 저장 권한 문제는 관련 기능만 차단하고 해결 방법을 표시한다. 등록 기기가 없으면 전송 화면 대신 등록 안내를 표시한다.

## 2. 전송 창

```text
┌ FTA                기록 설정 □ 고정 ┐
│ 기기                             + │
│ [컴퓨터]  [컴퓨터]  [컴퓨터]        │
│  이름      이름      이름          │
│ [파일 선택]                        │
│ [텍스트 또는 URL 입력             ]│
│                            [보내기]│
└────────────────────────────────────┘
```

메인 화면에는 내 컴퓨터 영역·탭을 두지 않는다. 기록과 설정은 상단 아이콘으로 각각 독립 OS 창을 열며 해당 창만 닫거나 다시 열 수 있다. 기기 아이콘의 상태 점은 온라인 초록·오프라인 회색·미등록 주황으로 표시하고 툴팁·접근성 이름에도 상태를 제공한다.

대상은 한 번에 한 기기를 선택한다. 다중 대상 동시 전송은 초기 범위에 넣지 않는다. 마지막 선택을 기억하고 기기 타일 선택 표시와 전송 버튼의 접근성 이름에 대상을 반영한다. 오프라인 등록 기기는 회색으로 보여주고 선택·전송을 막는다. 자동 발견된 미등록 기기는 주황 점과 최초 등록 확인 툴팁을 유지하며 선택·드롭할 수 있다. 최초 전송 시 수신자 한 번의 등록 허용을 기다리고 승인 후 전송을 이어간다. ID 입력·양쪽 등록 모드·비교값 버튼을 요구하지 않는다.

파일은 감지된 기기의 컴퓨터 아이콘 타일에 직접 놓으면 그 기기로 즉시 전송한다. 기존 선택과 관계없이 놓은 위치를 기준으로 하며 타일 바깥·등록된 오프라인 기기·전송 중 드롭은 전송하지 않는다. 별도 파일 놓기 영역은 없다. 파일 선택 버튼으로 만든 선택 목록은 현재 UI 세션에만 존재하며 오프라인 전달 대기열이 아니다. 창을 닫을 때 미전송 목록은 폐기한다. 디렉터리나 지원하지 않는 항목은 이름과 이유를 표시하고 자동 압축하지 않는다.

여러 파일은 이름·개수·전체 크기를 보여주고 항목별 결과를 제공한다. 고정 모드는 항상 위에 표시하는 작은 창이며 위치·크기를 저장한다. 화면 밖으로 이동한 저장 좌표는 다음 실행 시 현재 모니터 안으로 보정한다. 위젯은 별도의 OS 위젯 확장이 아니라 앱의 작은 창으로 구현한다.

텍스트는 Enter 또는 입력창 안의 화살표로 전송한다. Shift+Enter는 줄바꿈이며 한글 조합 확정 Enter와 키 반복은 전송하지 않는다. 성공 시 입력을 비우고 별도 성공 배너는 표시하지 않는다. 실패 안내와 입력 초안은 유지한다. 입력값 전체가 유효한 HTTP·HTTPS URL 하나면 URL로 분류하고, 그 외는 일반 텍스트다. 전송 성공 전까지 입력을 유지하며 실패 시 복구할 수 있게 한다. 클립보드를 자동 감시하거나 다른 컴퓨터에 자동 동기화하지 않는다.

## 3. 수신과 기록

파일 알림: `작업용 맥에서 파일 3개 수신`과 저장 위치 열기 동작. 텍스트·URL 알림은 발신 기기와 종류를 기본으로 표시하고 본문 전체는 내용 화면에서 보여준다. 알림에는 transfer_id만 연결하며 임의 경로나 URL을 실행 인자로 사용하지 않는다.

내용 화면은 발신 기기·수신 시각·본문·복사 버튼을 제공한다. URL이면 전체 주소와 링크 열기 버튼을 추가한다. 텍스트는 HTML로 렌더링하지 않는다. 앱 재실행을 동반한 알림 클릭도 같은 기록으로 연결한다. 기록이 삭제됐다면 ‘보관 기간이 지나 내용을 찾을 수 없습니다’를 표시한다.

기록 화면에는 송신·수신, 기기, 종류, 상태, 시각을 표시한다. 파일은 위치 열기, 텍스트는 내용 보기로 연결한다. 완료 기록에서 파일이 이동·삭제된 경우 그 사실을 표시한다. 기록 삭제는 내려받은 파일을 삭제하지 않는다. 결과 불명확 상태의 재전송은 중복 가능성을 먼저 보여준다.

## 4. 설정과 종료

기기 이름, 수신 폴더, 등록 기기·해제, 허용 네트워크, 로그인 시 실행, 고정 창, 알림 상태, 보관 정책, 진단 정보를 제공한다. 수신 폴더 변경은 새 항목에만 적용한다. 진단 정보에는 앱·프로토콜 버전, 바인딩 주소·포트, 권한 문제를 포함하되 개인키·메시지 본문은 제외한다.

트레이·메뉴 막대 메뉴는 `전송 창 열기 / 수신 기록 / 설정 / 앱 종료`다. 진행 중 앱 종료는 중단될 항목 수를 알리고 취소 또는 종료를 선택하게 한다. 창 닫기는 백그라운드 수신을 유지한다.

## 5. CLI 명령 계약

```sh
fta status
fta devices --json
fta pair open
fta pair connect <device-id-or-lan-address>
fta pair confirm <session-id>
fta pair cancel <session-id>
fta unpair <device-id>
fta send --to <device-id> ./photo.jpg ./video.mp4
fta text --to <device-id> --stdin
fta url --to <device-id> 'https://example.com'
fta transfer show <transfer-id>
fta transfer cancel <transfer-id>
fta inbox --limit 20
fta inbox show <transfer-id>
fta inbox delete <transfer-id>
fta config set receive-dir /srv/fta-inbox
fta service install
fta service start
fta service stop
fta service status
```

`pair open`과 `pair connect`는 양쪽에 비교값을 표시하며 `confirm`은 해당 로컬 세션만 확정한다. Linux에서도 최초 등록 시 양쪽 확인이 필요하다. 기기는 전체 ID 또는 고유한 ID 접두사로 지정하고 중복 이름은 오류로 처리한다. 텍스트는 인자 입력과 `--stdin`을 지원하며 동시에 사용하면 오류다. URL 인자는 셸에 맞게 인용하도록 도움말 예시를 제공한다.

송신 명령은 완료까지 기다리고 전송 ID를 즉시 출력한다. Ctrl+C는 취소 요청을 보낸 후 확인된 상태를 출력하며 수신 완료와 경쟁한 경우 이미 완료됐음을 알린다. `--json`에서는 stdout에 기계 처리용 결과만, 진행률과 진단은 stderr에 쓴다. 터미널 출력은 수신한 제어 문자·ANSI escape를 무해화한다. 원문이 필요한 경우 명시적인 파일 출력 옵션을 제공한다.

| 종료 코드 | 의미 |
|---|---|
| 0 | 성공 |
| 2 | 잘못된 인자·설정 |
| 3 | 대상 오프라인·접속 실패 |
| 4 | 인증·등록 오류 |
| 5 | 파일·저장·무결성 오류 |
| 6 | 부분 성공 |
| 7 | 결과 확인 필요 |
| 8 | 서비스 중지·로컬 IPC 오류 |
| 130 | 사용자 중단; 최종 상태는 출력에서 확인 |

CLI는 메일·브라우저·데스크톱 알림 없이 서버에서 모든 기본 기능을 사용할 수 있어야 한다.

## 작은 본체와 접기

본체 기본 크기는280×260이며 고정 다크의 자체 타이틀바를 사용한다. OS 기본 타이틀바를 사용하지 않는다. 기록·설정도 자체 타이틀바를 가진 독립 창이다. 본체 접기(마이너스) 버튼은 OS 작업표시줄 최소화 대신44×44 펼치기 버튼만 남긴다. 펼치면 이전 크기·입력·기기 선택을 복원하고 기기 아이콘 드롭을 사용할 수 있다. 접어도 엔진 수신을 중지하지 않으며 타이틀바 빈 공간·접힌 버튼을 끌어 이동할 수 있다.

## 집 네트워크 연결 설정

별도 설정 창에서 실제 연결 목록·방화벽 상태를 조회하고 집 연결 확인 후 연결 설정을 저장한다. Windows는 개인 프로필 전환을 별도로 선택하고 필요한OS승인을 받는다. Mac은 방화벽과 로컬 네트워크 개인정보 권한을 구분한다. 설정 저장과 서비스 재시작·실제 연결 검증은 구분한다. 본체 크기는 유지한다. [상세 흐름과 권한 경계](network-setup.md)를 따른다.

## 이름 갱신과 서비스 재시작

등록 기기의 이름은 매번 온라인 상태를 확인할 때 인증된 `/v1/hello` 응답에서 갱신·저장한다. mDNS의 이름으로 등록 정보를 바꾸지 않으며, 구버전 응답에 이름이 없으면 기존 이름을 유지한다. 새 이름 표시를 위해 양쪽 엔진에 이 변경이 필요하다.

설정의 서비스 재시작은 기존 동일 사용자 엔진에도 사용자 전용 IPC 정상 종료를 요청한다. IPC 연결 종료만으로 완료를 판단하지 않고 상태 디렉터리 잠금 해제를 기다린 뒤 번들 엔진을 시작한다. 독립 엔진에는 강제 종료를 사용하지 않으며 실패·시간 초과를 표시한다. 재시작·앱 종료·시작은 준비 확인까지 직렬화한다.

## 설정 그룹 탭

별도 설정 창을 네트워크·이 컴퓨터·앱 동작·기기 등록 탭으로 구분한다. 기본은 이 컴퓨터이며 탭 전환 시 입력 초안을 유지한다. 방향키·Home·End로 탭 선택과 포커스를 이동할 수 있다. 미등록 기기 아이콘 클릭은 기기 등록 탭으로 직접 연결한다. 본체 크기와 기존 다크 테마는 유지한다.

기기 등록 탭은 등록된 기기의 해제만 제공한다. 최초 송신·수신 확인과 대기·거절·취소 표시는 [최초 전송 등록 설계](first-send-registration.md)를 따른다.
