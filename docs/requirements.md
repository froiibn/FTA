# 요구사항 정의서

- 작성일: 2026-10-25
- 상태: 대화에서 확정한 요구사항 정리
- 대상 사용자: 여러 운영체제의 컴퓨터를 함께 사용하는 개인

## 1. 목적과 문제

파일을 옮길 때마다 파일질라로 FTP에 연결하거나, 짧은 텍스트와 URL을 메일로 보내고 다른 컴퓨터에서 다시 여는 과정이 번거롭다. 켜져 있는 내 기기에 파일과 정보를 적은 조작으로 전달할 수 있어야 한다.

## 2. 사용 환경

| 환경 | 수량 | 사용 방식 |
|---|---:|---|
| Windows | 1대 | 데스크톱 UI |
| macOS | 2대 | 데스크톱 UI |
| Linux 서버 | 1대 | 화면 없이 명령어(CLI)로 사용 |

모든 기기는 집 안의 같은 로컬 네트워크에서 사용한다. 기기가 켜져 있어도 전송 프로그램이 실행되지 않거나 연결이 불가능하면 전송할 수 없다.

## 3. 기능 요구사항

| ID | 요구사항 | 확정 수준 |

| FR-05 | 문서, 사진, 영상 등 파일을 전송할 수 있어야 한다. | 확정 |
| FR-06 | 간단한 텍스트와 URL을 전송할 수 있어야 한다. | 확정 |

| FR-16 | Windows 설치 프로그램은 Program Files를 기본 설치 위치로 제시하고 사용자가 다른 설치 폴더를 선택할 수 있어야 한다. | 사용자 요청으로 확정 |
| FR-17 | 감지된 컴퓨터에 최초 전송하면 수신자만 한 번 기기 등록을 확인하고, 이후 등록된 온라인 기기에 바로 전송한다. 양쪽 수동 등록 모드·ID 입력은 기본 흐름에서 제거한다. | 사용자 요청으로 확정 |

## 4. 제외 범위

- 외부 네트워크에서 접속하거나 인터넷을 통한 전송
- 상대 기기의 폴더 목록 조회, 파일 탐색, 파일 가져오기
- 꺼져 있거나 연결되지 않은 기기를 위한 대기열 및 나중 전달
- 전송 건마다 수신 승인 요청
- 수신 건마다 저장 경로 선택

상대 기기의 ‘자원 공유’라는 초기 표현은 이후 대화에 따라 선택한 파일과 정보를 보내는 기능으로 한정한다.

## 5. 후속 기술 결정

사용자 결정으로 공통 엔진·Linux CLI·서비스는 Rust, 데스크톱 공통 화면은 TypeScript, Windows·macOS 데스크톱 프레임워크는 Tauri 2로 확정했다. 이 결정은 기능 요구사항과 구분되는 구현 제약이다. Linux 서버에는 Tauri·WebView를 포함하지 않는다.

## 6. 아직 확정하지 않은 사항

기기 등록과 신뢰 설정, 구체적인 UI, 실패와 취소 처리, 이름이 같은 파일 처리, 수신 기록 보존, 시작 프로그램 등록, 폴더 전송, 파일 크기와 동시 전송 제한은 설계 대상이다. 아래 분석서와 설계서의 제안은 사용자 확정 요구사항과 구분한다.

## 초기 사용 네트워크 설정 추가

사용자가 Windows와macOS 모두 앱에서 집 네트워크 초기 설정을 지원하도록 확정했다. 실제 연결과OS설정을 조회하고 사용자가 집 연결임을 확인한 뒤 필요한 네트워크 프로필·FTA 방화벽 설정을 적용한다. 필요한 관리자 권한은OS승인으로 요청하며, 보호 기능 전체 해제나 승인 우회를 하지 않는다. 상세 흐름은 [초기 연결 설계](network-setup.md)를 따른다.

최초 등록 변경은 [최초 전송 등록 설계](first-send-registration.md)를 따른다. 승인 대기는 활성 온라인 요청에만 한정하며 오프라인 전송 예약이 아니다.

## iOS 우선 확장 (2026-10-29)

사용자 요청으로 같은 LAN의 iOS·Android 및 기존 Windows·macOS·Linux 사이 파일·텍스트·URL 송수신을 제품 목표에 추가한다. 현재 구현은 별도 폴더의 iOS 초안을 우선한다. 최초 수신자 한 번의 등록 승인·등록된 온라인 기기만 전송·승인 전 본문 차단 정책을 유지한다.

이번 사용자 지시로 iOS는 SwiftUI 기본 컨트롤과 탭바를 사용하는 네이티브 화면으로 구현한다. Windows·macOS의 TypeScript·Tauri 2 결정은 유지한다. 컴퓨터는 PC 버전의 기존 아이콘, 모바일은 휴대폰 아이콘을 사용한다. Android 구현 순서·화면 기술·전체 최소 지원 OS와 후속 세부 범위는 미확정이다. [iOS 초안과 경계](platforms/ios.md).

## 전송 대상 표시 정책 (2026-10-29)

사용자 요청으로 Windows·macOS·iOS 전송 대상 목록에는 현재 연결 가능한 기기만 표시한다. 오프라인 등록 정보는 전송 목록에서 제외하며 설정의 등록 해제 관리에만 유지한다. 미등록 기기는 현재 접속 가능한 경우에만 최초 승인 대상으로 표시하고 본문·신뢰 정책을 유지한다. 모바일의 Wi-Fi/LAN 연결이 끊기면 로컬 대상 목록·선택을 즉시 비우며, 상대 모바일의 갑작스러운 연결 끊김은 다음 인증·접속 확인 실패 시 목록에서 제외한다.

## 모바일 입력·미디어 구분 (2026-10-29)

사용자가 모바일의 텍스트/URL 선택 영역을 제거하고 하나의 여러 줄 입력에서 그대로 전송하도록 요청했다. HTTP(S) 단일 주소만 자동으로 URL 종류를 사용해 수신 측 링크 열기를 유지하며 그 외는 원문 텍스트로 보낸다. 사진은 갤러리 선택·새 촬영, 파일은 기존 파일 앱 선택으로 나눈다. 사진과 파일 선택 초안은 독립적으로 유지한다. iOS 대상 아이콘은 흰색 윤곽과 PC와 같은 온라인/미등록 상태 점을 사용하고 PC 목록에서도 iOS·Android는 휴대폰으로 표시한다. 수정 후 연결된 iPhone에 기존 앱을 업데이트한다.

## iOS 신뢰 유지·화면 변경 (2026-10-30)

신뢰한 연결은 재접속·앱 재시작·기기 재부팅 후에도 복원하고 송수신 사용·기기 이름 등 기존 설정을 유지한다. 기존 설정 항목은 삭제하지 않는다. 현재 확인 가능한 인터페이스·허용 CIDR 대역을 영속 저장하며 DHCP 주소 변경과 일시 단절은 신뢰 철회가 아니다. 명시적으로 신뢰를 끄면 해당 범위의 승인을 제거한다. SSID·라우터 고유성 검증을 구현한 것으로 해석하지 않는다.

모바일 전송 대상은 PC처럼 아이콘을 가로로 배치하고 스크롤바 없이 터치로 좌우 탐색·선택한다. 사진·파일을 한 첨부 영역으로 합치고 감싸는 박스 없이 흰색 글자의 사진/파일 버튼 둘을 가로로 둔다. 사진 버튼은 갤러리 선택/촬영을 제공한다. 메시지는 한 줄에서 네 줄까지 늘어나는 입력창과 내부 원형 아이콘으로 전송하고 네 줄 초과 시 내부 스크롤한다. 보이는 ‘보내기’ 글자는 제거하되 접근성 이름은 유지한다. 네이티브 소재를 활용한 글래스모피즘과 데스크톱과 같은 앱 아이콘을 적용한다.

PC 0.1.2 배포와 Windows 후속 빌드를 변경하지 않는다. 자동 업데이트는 0.1.3 후속 계획이며 이번 작업에서 착수하지 않는다.

## iOS 스크롤·전송 피드백 보완 (2026-10-30)

메인 상단의 앱 아이콘·FTA 이름·작은 File Transfer Anything 문구를 포함한 본문이 스크롤되도록 하고, 접히며 남는 상단 고정 내비게이션 영역을 제거한다. 메시지 입력창은 후속 사용자 정정에 따라 기존 하단 위치를 유지한다. 연결 가능 기기 윤곽을 조금 확대하고 상태 점은 카드 바깥이 아닌 기기 윤곽에 붙인다. 사진 소스 팝오버는 사진 버튼 바로 아래에 표시한다. 빈 영역을 탭하면 메시지 키보드를 닫는다.

사진·파일·텍스트 전송은 대상 기기 아이콘 테두리로 진행 상태를 표시한다. 실제 파일 바이트 진행률을 사용하며 진행률이 없는 등록 대기·텍스트는 가짜 퍼센트를 만들지 않는다. 수신 측 저장 완료 응답을 받은 경우에만 해당 대상에 체크 아이콘을 1.5초간 표시하고 제거한다. 화면에 완료 문구·완료 상태 카드를 계속 남기지 않는다. 부분 완료·실패·취소·결과 불명은 성공으로 표시하지 않고 기록과 오류 확인을 유지한다. 전송 기록 글자는 흰색으로 표시한다.
