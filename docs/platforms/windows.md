# Windows 상세 설계안

작성일: 2026-10-25. 대상은 Windows 11, AMD Ryzen 5 5600X(6-core, x86-64) PC 1대다. 이 정보는 사용자 확인값이며 실제 설치·실행 검증과 최소 지원 OS 범위는 별개로 관리한다.

## 1. 실행 구조

사용자 세션에서 `fta-engine.exe`와 트레이 UI를 실행한다. UI는 TypeScript 공통 화면과 Tauri 2 Rust 호스트로 구성한다. TypeScript는 Tauri 명령을 호출하고 Rust 호스트가 현재 사용자만 접근 가능한 named pipe로 엔진을 제어한다. 엔진은 Tauri 실행에 의존하지 않는다. Windows Service와 SYSTEM 권한은 초기 설계에 사용하지 않는다.

일반 창을 닫아도 트레이와 엔진을 유지하고 메뉴의 종료로 둘 다 종료한다. 로그인 시 자동 실행은 사용자 선택 설정으로 등록한다. 로그아웃하면 수신도 종료한다. 잠금 상태에서는 프로세스가 실행 중이고 OS가 절전하지 않으면 수신을 유지하되 알림 표시는 OS 설정에 따른다. 로그인 전 수신은 초기 범위에서 지원하지 않는다.

## 2. UI와 OS 연결

- 트레이 아이콘: 온라인 기기 수, 전송 창, 기록, 설정, 종료.
- 고정 창: 작업 표시줄 전체 창과 별개로 작게 유지할 수 있는 전송 패널.
- 드롭: Tauri의 파일 드롭 이벤트로 Explorer의 일반 파일을 받고 디렉터리·가상 파일 드롭은 명시적으로 거부한다. 관리자 권한 실행을 기본으로 하지 않는다.
- 알림: 로컬 앱 알림과 클릭 활성화 등록을 구현하고 transfer_id를 수신 기록 화면으로 라우팅한다. 프로세스가 이미 실행 중이면 기존 UI에 전달한다.
- 클립보드: 사용자 복사 동작으로 텍스트 기록.
- 파일 위치: 파일 탐색기에서 저장 파일 선택 또는 수신 폴더 열기.

Tauri API·플러그인으로 트레이·알림·클립보드·파일 열기를 연결하고 부족한 알림 활성화 기능은 Windows Rust 어댑터로 보완한다. TypeScript에서 임의 셸 명령을 실행하도록 노출하지 않는다. 패키징 방식에 따라 앱 알림 등록과 활성화를 검증한다. Windows App SDK 공식 문서는 비패키지 앱의 알림 클릭을 위한 등록 동작을 설명한다. 알림 비허용·집중 모드에서도 수신 완료는 기록한다. [Microsoft: 앱 알림](https://learn.microsoft.com/windows/apps/develop/notifications/app-notifications/app-notifications-dotnet)

## 3. 파일·설정·키

| 항목 | 기준 경로·방식 |
|---|---|
| 기본 수신 폴더 | Windows Known Folder API로 얻은 Downloads 아래 `FTA` |
| 상태·설정 | `%LOCALAPPDATA%\FTA` 아래 DB·설정·회전 로그 |
| 임시 수신 | 사용자가 지정한 수신 폴더 아래 `.fta-partials` |
| 인증키 | DPAPI 사용자 범위로 보호한 키 파일 후보 |
| IPC 접근 | 현재 사용자 SID만 허용하는 pipe ACL |

경로는 문자열로 사용자 홈을 조합하지 않고 OS API를 사용한다. 긴 경로·한글·이모지·대소문자 충돌·예약 이름·잠긴 파일을 검증한다. 백신 등의 파일 점유로 최종 이동이 실패하면 완료로 표시하지 않고 오류와 재시도 방법을 제공한다. 수신 폴더는 로컬 쓰기 가능한 경로를 권장하며 네트워크 공유 경로는 v1 검증 범위에서 제외한다.

## 4. 네트워크와 방화벽

집 네트워크에 해당하는 Private 프로필과 로컬 대역에 한정한 앱 인바운드 규칙을 안내한다. 공용 프로필 허용이나 방화벽 전체 해제는 하지 않는다. TCP 수신 포트와 발견 트래픽이 각각 통과하는지 확인하고 자동 규칙 설정에 권한이 필요하면 설치 단계에서 명시적으로 처리한다. [Microsoft: 방화벽 프로필](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ics/windows-firewall-profiles)

Wi-Fi·유선 전환과 절전 복귀 시 인터페이스·주소를 재검색한다. Windows 방화벽 허용과 앱의 등록 기기 인증은 별도 계층으로 유지한다.

## 5. 배포와 검증

Tauri 번들러 기반 사용자별 설치 프로그램을 우선 검토하고 Windows WebView2 런타임의 설치·탐지 정책을 검증한다. 또한 엔진·UI·알림 식별자의 경로를 안정적으로 유지한다. 설치·업데이트 후 알림 클릭 활성화, 자동 실행, 방화벽 규칙이 유효한지 검증한다. 업데이트는 진행 중 전송이 없는 시점에 수동 적용하는 초기 정책이다. 제거 시 수신 파일은 보존하고 로컬 설정 삭제는 선택할 수 있게 한다.

필수 검증: Explorer 드롭, 다른 권한 프로세스와의 드롭 제약, 트레이 유지, 잠금·로그아웃·절전, 앱 종료 후 알림 클릭, 비ASCII·긴 파일명, 파일 점유, 디스크 부족, Private/Public 네트워크 전환, macOS·Linux와 양방향 전송.

## 6. Windows 테스트 패키지 만들기

Windows 11 x64 PC에서 `packaging/windows/build.ps1`을 실행한다. 현재 사용자용 NSIS, WebView2 다운로드 부트스트래퍼와 엔진·MCP 동봉 설정을 적용하며 산출물·해시·빌드 로그를 새 폴더에 모은다. [준비·설치·검증 절차](../../packaging/windows/README.md)를 따른다. 스크립트 준비와 Windows에서의 실제 빌드·설치 통과는 구분하며 현재 후자는 미검증이다.
