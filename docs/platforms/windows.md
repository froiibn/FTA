# Windows 상세 설계안

작성일: 2026-10-25. 대상은 Windows 11, AMD Ryzen 5 5600X(6-core, x86-64) PC 1대다. 이 정보는 사용자 확인값이며 실제 설치·실행 검증과 최소 지원 OS 범위는 별개로 관리한다.

## 1. 실행 구조

사용자 세션에서 `fta-engine.exe`와 트레이 UI를 실행한다. UI는 TypeScript 공통 화면과 Tauri 2 Rust 호스트로 구성한다. TypeScript는 Tauri 명령을 호출하고 Rust 호스트가 현재 사용자만 접근 가능한 named pipe로 엔진을 제어한다. 엔진은 Tauri 실행에 의존하지 않는다. Windows Service와 SYSTEM 권한은 초기 설계에 사용하지 않는다.

일반 창을 닫아도 트레이와 엔진을 유지하고 메뉴의 종료로 둘 다 종료한다. 로그인 시 자동 실행은 사용자 선택 설정으로 등록한다. 로그아웃하면 수신도 종료한다. 잠금 상태에서는 프로세스가 실행 중이고 OS가 절전하지 않으면 수신을 유지하되 알림 표시는 OS 설정에 따른다. 로그인 전 수신은 초기 범위에서 지원하지 않는다.

## 2. UI와 OS 연결

- 트레이 아이콘: 온라인 기기 수, 전송 창, 기록, 설정, 종료.
- 고정 창: 작업 표시줄 전체 창과 별개로 작게 유지할 수 있는 전송 패널.
- 드롭: Tauri의 파일 드롭 이벤트로 Explorer의 일반 파일을 받고 디렉터리·가상 파일 드롭은 명시적으로 거부한다. 관리자 권한 실행을 기본으로 하지 않는다.
- 알림: 로컬 앱 알림과 클릭 활성화 등록을 구현하고 transfer_id를 수신 기록 화면으로 라우팅한다. 프로세스가 이미 실행 중이면 기존 UI에 전달한다.
- 클립보드: 사용자 복사 동작으로 텍스트 기록.
- 파일 위치: 파일 탐색기에서 저장 파일 선택 또는 수신 폴더 열기.

Tauri API·플러그인으로 트레이·알림·클립보드·파일 열기를 연결하고 부족한 알림 활성화 기능은 Windows Rust 어댑터로 보완한다. TypeScript에서 임의 셸 명령을 실행하도록 노출하지 않는다. 패키징 방식에 따라 앱 알림 등록과 활성화를 검증한다. Windows App SDK 공식 문서는 비패키지 앱의 알림 클릭을 위한 등록 동작을 설명한다. 알림 비허용·집중 모드에서도 수신 완료는 기록한다. [Microsoft: 앱 알림](https://learn.microsoft.com/windows/apps/develop/notifications/app-notifications/app-notifications-dotnet)

## 3. 파일·설정·키

| 항목 | 기준 경로·방식 |
|---|---|
| 기본 수신 폴더 | Windows Known Folder API로 얻은 Downloads 아래 `FTA` |
| 상태·설정 | `%LOCALAPPDATA%\FTA` 아래 DB·설정·회전 로그 |
| 임시 수신 | 사용자가 지정한 수신 폴더 아래 `.fta-partials` |
| 인증키 | DPAPI 사용자 범위로 보호한 키 파일 후보 |
| IPC 접근 | 현재 사용자 SID만 허용하는 pipe ACL |

경로는 문자열로 사용자 홈을 조합하지 않고 OS API를 사용한다. 긴 경로·한글·이모지·대소문자 충돌·예약 이름·잠긴 파일을 검증한다. 백신 등의 파일 점유로 최종 이동이 실패하면 완료로 표시하지 않고 오류와 재시도 방법을 제공한다. 수신 폴더는 로컬 쓰기 가능한 경로를 권장하며 네트워크 공유 경로는 v1 검증 범위에서 제외한다.

## 4. 네트워크와 방화벽

집 네트워크에 해당하는 Private 프로필과 로컬 대역에 한정한 앱 인바운드 규칙을 안내한다. 공용 프로필 허용이나 방화벽 전체 해제는 하지 않는다. TCP 수신 포트와 발견 트래픽이 각각 통과하는지 확인하고 자동 규칙 설정에 권한이 필요하면 설치 단계에서 명시적으로 처리한다. [Microsoft: 방화벽 프로필](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ics/windows-firewall-profiles)

Wi-Fi·유선 전환과 절전 복귀 시 인터페이스·주소를 재검색한다. Windows 방화벽 허용과 앱의 등록 기기 인증은 별도 계층으로 유지한다.

### 앱 네트워크 설정 어댑터

Windows 어댑터는 Network List Manager와 실제 어댑터 주소로 연결·프로필·집 대역을 조회한다. 초기 자동 설정은 전체 서브넷이 RFC1918에 속하는 연결된 IPv4 후보를 대상으로 한다. 연결 선택 ID에는 어댑터·NLM 네트워크 ID·주소·프리픽스 상태를 묶어, 확인 후 다른 네트워크가 같은 어댑터/IP를 사용해도 이전 선택을 재사용할 수 없게 한다. 요청한 Public→Private 전환 뒤에도 같은 연결을 재조회해야 하므로 프로필 값은 선택 ID에서 제외하고, 권한 요청 계획에 별도로 담아 적용 직전에 재검증한다. 집 연결 확인 값이 없거나 네트워크가 바뀌면 권한 요청 전에 거부한다. Domain·알 수 없는 프로필과 여러 연결이 공유하는 Public 프로필의 자동 전환은 지원하지 않는다.

필요한 변경은 별도 `fta-network-helper.exe`를 Windows `runas`로 실행하여 OS UAC 승인을 받는다. UI와 엔진은 승격하지 않는다. TypeScript에서 명령·실행 경로·CIDR를 받지 않으며 Rust가 설치 위치와 OS 주소에서 파생한다. helper에는 일회용 pipe 식별자와 부모 PID만 인자로 전달하고, 실제 데이터는 현재 사용자 전용 named pipe로 보낸다. 양단 PID·현재 사용자·180초 요청 만료·동일 설치 폴더의 엔진·현재 연결 상태를 helper가 다시 검증한다. 다른 관리자 계정으로 승인하는 방식은 현재 사용자 pipe 접근을 우회하지 않고 실패한다.

관리 규칙은 사용자별 고정 이름으로 중복을 막는다. 프로그램·Private 프로필·선택 인터페이스·로컬 IP·실제 집 CIDR의 원격 주소를 모두 제한하고, 포트가 동적으로 정해지는 기기 등록 때문에 TCP는 해당 엔진의 모든 로컬 포트를 허용한다. 자동 발견을 켰을 때만 UDP 5353을 추가한다. mDNS 멀티캐스트 수신을 위해 UDP 로컬 주소는 선택 IP와 표준 그룹 `224.0.0.251`을 포함한다. 발견을 끄면 이 도우미가 소유한 UDP 규칙만 제거한다. 경로 갱신 시 기존 소유 규칙을 먼저 비활성화한 뒤 완전히 제한된 새 규칙으로 대체하며, 다른 소유 표식의 동명 규칙은 덮어쓰지 않는다.

전체 방화벽·공용 프로필·모든 수신 차단·GPO 정책은 완화하지 않는다. 적용 후 실제 프로필과 규칙을 재조회한다. 취소·권한 거부·선택 변경·실패·부분 적용을 구분하며, 적용 시작 확인 이후 응답이 유실되면 변경 없음으로 단정하지 않는다. OS 규칙 확인은 실제 기기 연결 성공을 보장하지 않으므로 엔진 설정 저장·재시작·LAN 송수신 검증은 별도로 수행한다.

개발 검증: 실제 공통 DTO와 연결한 네이티브 읽기 전용 조회·미적용 규칙 객체·권한 경계·동시 실행 관련 검사 19개를 포함해, 코드 `2ea7cae`의 로컬 Windows 패키징 스크립트에서 headless 87개·desktop 9개 검사와 fmt·Clippy·TypeScript/Vite·네이티브 빌드가 통과했다. 생성한 NSIS를 현재 사용자에게 설치해 종료 코드 0, 동봉된 네 바이너리의 설치 후 해시 일치, 엔진·앱 실행, 기존 등록·설정 보존과 Mac 온라인 상태를 확인했다. 설치본의 실제 설정 화면에서 연결 주소·집 CIDR·Private 프로필이 표시되고, 집 연결 확인 전에는 적용 버튼이 비활성화되며 연결 실패 안내가 남지 않는 것을 확인했다. 실제 UAC 승인·취소·다른 계정 거부와 실제 규칙 생성·갱신·제거는 아직 추가 검증이 필요하다. 현재 사용자 연결과 기존 방화벽 규칙은 변경하지 않았다.

### 여러 창의 IPC 연결 경합

설치 후 실제 설정 창을 확인하면서 엔진이 정상인데도 연결 실패 안내가 나타나는 현상을 발견했다. 8개 동시 실행으로 24개 읽기 요청을 보내 한 번의 Windows `ERROR_PIPE_BUSY`(231)를 재현했다. 엔진이 수신 pipe 인스턴스를 교체하는 짧은 구간을 서비스 종료로 오판한 원인이므로, Windows 클라이언트는 요청 프레임을 쓰기 전 연결 단계에서만 최대 5초 동안 이 오류를 재시도한다. 서비스 부재·권한 거부는 즉시 실패하고 프레임 전송 이후에는 재시도하지 않아, 이미 적용됐을 수 있는 설정이나 전송 요청을 중복 실행하지 않는다. 실제 사용자 전용 pipe로 교체 리스너 연결·유한 대기·없는 서비스 즉시 실패를 검사했다. 수정된 클라이언트로 같은 8개 동시 실행·24개 요청을 다시 보내 24개 모두 성공했다. 보조 창의 조회 오류도 해당 조회가 정상 복구된 경우에만 지우며 사용자 전송·권한 작업의 실패 안내는 유지한다.

### 실행 파일의 실제 동일성

방화벽 규칙의 `ApplicationName`과 요청한 엔진은 경로 문자열의 대소문자를 무시해 비교하지 않는다. Windows 경로 별칭은 같은 파일을 가리킬 수 있고, 대소문자를 구분하는 NTFS 디렉터리에서는 대소문자만 다른 별개 파일이 존재할 수 있기 때문이다. 규칙 조회는 두 경로의 실제 파일 ID가 같을 때만 허용 상태로 판단하고, 파일 부재·조회 실패는 허용으로 처리하지 않는다. 엔진 검증도 실행 중인 앱·helper 설치 폴더의 고정 `fta-engine.exe`와 요청 경로가 실제로 같은 파일인지 확인한 뒤 기존 헤더 검사를 수행한다. 입력 별칭은 동일성 증거로만 사용하며 반환값은 고정 설치 엔진의 정규 경로로 제한한다. 외부 하드링크 경로를 반환해 그 폴더의 helper를 선택하지 않도록 하기 위해서다. 임시 외부 하위 폴더의 하드링크를 입력해도 설치 엔진 경로가 반환되는 회귀를 수정 전 실패·수정 후 통과로 확인했다.

회귀 검사는 설치본 대신 임시 파일과 실제 방화벽에 등록하지 않은 COM 규칙 객체를 사용한다. 하드링크 별칭 허용, 내용이 같은 별개 파일 거절, 고정 설치 파일 삭제 후 남은 별칭 거절과 없는 경로 거절을 확인한다. 두 신규 검사는 기존 문자열 비교에서 실패하고 파일 ID 비교로 수정한 뒤 통과했다. 대소문자만 다른 별개 파일의 전용 검사는 이미 대소문자를 구분하는 TEMP 파일시스템에서 명시적으로 실행하도록 `#[ignore]` 처리했으며 이번에는 실행하지 않았다. 임시 디렉터리 속성 변경 명령이 자동 승인 검토에서 차단돼 해당 변경을 우회하거나 OS·방화벽 설정을 변경하지 않았다.

이 보완 후 Windows 로컬 headless 89개·desktop 9개 검사가 통과했고 전용 NTFS 검사 1개는 위 조건으로 미실행이다. fmt·headless/helper/desktop Clippy·desktop check·TypeScript/Vite 빌드도 통과했다. 이 보완은 후속 소스 수정이며 앞서 검증한 `2ea7cae` 설치 파일에는 포함되지 않는다. 요청에 따라 기존 설치본을 유지하고 새 패키징·재설치·GitHub Actions·릴리즈 게시는 수행하지 않는다.

## 5. 배포와 검증

Tauri 번들러 기반 사용자별 설치 프로그램을 우선 검토하고 Windows WebView2 런타임의 설치·탐지 정책을 검증한다. 또한 엔진·UI·알림 식별자의 경로를 안정적으로 유지한다. 설치·업데이트 후 알림 클릭 활성화, 자동 실행, 방화벽 규칙이 유효한지 검증한다. 업데이트는 진행 중 전송이 없는 시점에 수동 적용하는 초기 정책이다. 제거 시 수신 파일은 보존하고 로컬 설정 삭제는 선택할 수 있게 한다.

필수 검증: Explorer 드롭, 다른 권한 프로세스와의 드롭 제약, 트레이 유지, 잠금·로그아웃·절전, 앱 종료 후 알림 클릭, 비ASCII·긴 파일명, 파일 점유, 디스크 부족, Private/Public 네트워크 전환, macOS·Linux와 양방향 전송.

## 6. Windows 테스트 패키지 만들기

Windows 11 x64 PC에서 `packaging/windows/build.ps1`을 실행한다. 현재 사용자용 NSIS, WebView2 다운로드 부트스트래퍼와 엔진·MCP 동봉 설정을 적용하며 산출물·해시·빌드 로그를 새 폴더에 모은다. [준비·설치·검증 절차](../../packaging/windows/README.md)를 따른다. Windows 네이티브 검사·설치 파일 생성·현재 사용자 설치와 실행·트레이 유지·종료와 재실행, Private 프로필에서 Mac 한 대와의 CLI 엔진 양방향 파일·무결성·동일 이름 보존을 확인했으며 [검증 기록](../implementation-status.md)에 환경과 결과를 남겼다. 다른 기기 조합·GUI 드롭·알림 표시와 클릭·자동 발견·자동 실행·제거는 추가 검증이 필요하다.

## 초기 연결 지원 추가

실제 집 연결 선택·개인 프로필 전환·엔진 전용 방화벽 설정과 OS승인을 앱에서 지원한다. [공통 계약과 흐름](../network-setup.md)에 구현·검증 범위를 기록했다. 실제 관리자 승인과 규칙 변경 시험은 미완료다.
