# 최초 전송 시 수신자 등록 확인

사용자 확정 변경(2026-10-28): 감지된 컴퓨터를 선택해 파일·텍스트·URL을 보내면 상대에서 처음 한 번 등록을 확인하고, 이후 등록된 온라인 기기로 즉시 전송한다.

## 계획·검토

기존 280×260 본체·다크 테마·기기 상태 점과 파일 스트리밍 구조를 유지한다. 미등록 기기도 선택·드롭 대상으로 허용하되 온라인 인증을 완료한 초록 상태로 꾸미지 않는다. 수동 ID·주소 입력과 양쪽 등록 모드·비교값 버튼은 데스크톱에서 제거한다. 등록된 기기 해제는 설정에 남긴다.

송신 시 실제 승인 대기를 진행 영역에 표시하고 취소를 제공한다. 수신 본체만 현재 엔진 요청을 조회해 기기 이름·주소와 등록 허용/거절 네이티브 창을 표시한다. 설정 창이나 미리보기는 승인 창을 생성하지 않는다. 기존 파일 선택 권한과 메시지 크기·URL 검사를 유지한다.

이 환경에 frontend-design 스킬 파일은 제공되지 않아 기존 UI 설계와 프로젝트 지침의 계획·검토·구현 흐름을 문서화했다. 사용자 지시로 Computer Use와 자동 테스트·실기·설치를 수행하지 않으며 시각 검증은 미수행으로 남긴다. 가짜 온라인 기기나 가짜 전송 결과를 넣지 않는다.

## 인증과 전송 경계

- 선택된 집 인터페이스에서 별도 등록 TLS 리스너를 자동 준비하고 기존 등록 mDNS 유형에 광고한다. 일반 파일 수신 포트는 등록된 인증서 pin을 계속 요구한다.
- 첫 전송 요청은 종류·항목 수·전송 ID만 등록 의도로 보낸다. 파일 본문·텍스트·URL·로컬 경로는 승인 전에 상대에게 보내지 않는다.
- 전송 동작을 송신자의 동의로 보고 수신자의 한 번의 명시적 허용으로 최초 pin을 저장한다. TLS 서명, 인증서와 요청 기기 정보·연결 출발지 바인딩을 확인한다. 수신자 승인 전에는 기기 이름·발견 정보만으로 신원을 인증했다고 주장하지 않는다. 이전 양쪽 비교값 수동 검증과 다른 최초 신뢰 정책이며, 이를 생략 없이 동일한 보안 보장이라고 부르지 않는다.
- 서버 등록 세션 nonce·인증서 비교 transcript를 유지하고 승인 요청 의도를 양쪽에서 확인한다. 구버전은 의도를 되돌려주지 않으므로 자동 승인 방식으로 조용히 대체하지 않고 업데이트가 필요하다고 알린다.
- 기존 ID와 다른 키는 자동 덮어쓰지 않는다. 이미 수신자가 허용한 동일 키에는 다시 묻지 않는다. 등록 해제 후에는 다시 확인한다.
- 일반 MCP 전송은 계속 등록 기기만 허용한다. 데스크톱 전용 전송과 CLI의 명시적인 --request-registration만 등록 확인을 시작한다.
- 등록 허용은 신뢰 저장이며 전송 완료가 아니다. 이후 기존 송신 경로가 등록·온라인 검증, 파일 재검증, 스트리밍, 최종 저장 확인을 수행한다.

## 실패·취소·복구

활성 요청은 메모리에 한정하며 오프라인 전달 대기열이나 재시도 예약으로 저장하지 않는다. 거절은 즉시 종결 상태로 전달하고 동일 TLS 공개키의 반복 요청을 30초 제한한다. 승인 예산은 실제 요청 시점부터 120초이며 송신 측도 로컬 시간 제한을 둔다. 취소·만료·네트워크 변경에는 승인 의도와 전송 준비를 해제하고 초안을 보존한다. 승인과 취소가 경쟁해 이미 저장된 신뢰는 임의 삭제하지 않지만 취소된 본문을 나중에 보내지 않는다.

## CLI

수신자: `fta registration requests` → `fta registration accept <session-id>` 또는 `reject`.
최초 송신: `fta --request-registration text --to <device-id> "내용"` 등.
이후에는 기존 send/text/url을 사용한다. 기존 pair 명령은 수동 비교를 원하는 고급 CLI 흐름으로 유지한다.

## 검증

계획: 승인 전 payload·pin 미생성, 수신 허용 후 원래 전송 완료, 재전송 시 승인 생략, 거절·취소·만료·네트워크 변경·키 변경·오래된 상태 응답의 등록 부활 차단, 기존 MCP 제한과 파일 권한 보존을 확인한다. 이 문서는 검사 통과 기록이 아니다.
