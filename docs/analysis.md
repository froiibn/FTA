# 요구사항 분석서

- 작성일: 2026-10-25
- 기준: [요구사항 정의서](requirements.md)
- 상태: 초기 분석 완료, 세부 정책은 설계 제안

## 1. 제품의 중심

이 앱은 개인 기기 사이의 즉시 전송 도구다. 파일 서버나 폴더 동기화 도구가 아니며, 송신자가 현재 사용하는 기기에서 전달할 내용을 선택한다. 대상 기기를 찾고 전송을 시작하는 데 필요한 조작을 줄이는 것이 주요 가치다.

## 2. 주요 사용 흐름

| 상황 | 기대 흐름 | 관련 요구사항 |
|---|---|---|
| 맥에서 윈도우로 사진 전달 | 대상 선택 → 파일 드래그 → 자동 저장 → 수신 알림 | FR-01~05, FR-07~09 |
| 윈도우에서 맥으로 URL 전달 | URL 입력 또는 붙여넣기 → 대상 선택 → 전송 → 알림 클릭 → 내용 확인·복사·열기 | FR-06~07, FR-09~11 |
| 데스크톱에서 서버로 파일 전달 | 서버 선택 → 전송 → 서버의 수신 폴더에 저장 | FR-01~03, FR-07~08, FR-12 |
| 서버에서 맥으로 텍스트 전달 | CLI로 대상과 내용 지정 → 전송 → 맥에서 알림·내용 확인 | FR-06~07, FR-09~12 |
| 대상이 연결되지 않음 | 전송 불가 상태 표시; 나중 전달을 위한 보관은 하지 않음 | FR-02, 제외 범위 |

## 3. 분석으로 도출한 설계 필요사항

다음은 기능을 안정적으로 제공하기 위한 제안이며, 추가로 확정된 사용자 요구사항은 아니다.

- 매번 주소를 입력하지 않도록 기기 자동 발견과 사람이 읽을 수 있는 기기 이름이 필요하다.
- 자동 수신은 등록된 내 기기에 한정하는 것이 적절하다. 같은 네트워크라는 사실만으로 수신 권한을 부여하지 않는다. 최초 등록과 매번 수신 승인은 별개다.
- 수신기는 백그라운드에서 실행되어야 한다. 시작 시 자동 실행 여부는 설정으로 설계한다.
- Linux는 데스크톱 알림 대신 CLI 조회와 로그로 수신 사실과 텍스트 내용을 확인할 수 있어야 한다.
- 파일 저장 성공을 확인한 뒤 송신자에게 완료를 알려야 한다. 연결 끊김이나 디스크 부족을 성공으로 표시해서는 안 된다.
- 전송 중 파일과 완료 파일을 구분하고, 같은 이름의 기존 파일이 덮어써지지 않도록 정책이 필요하다.
- 텍스트·URL 내용은 알림 클릭 후 확인할 수 있도록 수신 측에 보관할 필요가 있다. 보존 기간과 용량은 미정이다.

## 4. 초기 검증 기준

| 범위 | 검증 기준 |
|---|---|
| 운영체제 호환 | Windows·macOS·Linux 각 조합에서 양방향 파일·텍스트·URL 전송 가능 |
| 드래그 전송 | 데스크톱 전송 영역에 놓은 파일을 선택한 기기로 보낼 수 있음 |
| 자동 수신 | 등록된 기기에서 보내면 수신 승인 창 없이 설정 폴더에 저장됨 |
| 수신 내용 | 파일은 송신 원본과 일치하고 텍스트는 줄바꿈과 유니코드를 유지함 |
| 데스크톱 알림 | OS 알림이 허용된 환경에서 수신 완료 알림을 제공하고 텍스트·URL 내용을 열 수 있음 |
| URL 처리 | 내용을 복사할 수 있고 사용자가 열기를 선택하면 브라우저로 열림 |
| CLI | GUI 없이 대상 조회, 전송, 수신 내용 확인이 가능함 |
| 오프라인 | 연결 불가능한 기기에 성공으로 표시하지 않고 나중 전달도 하지 않음 |
| 실패 처리 제안 | 연결 중단·저장 실패 시 오류를 표시하고 완료 파일로 취급하지 않음 |
| 신뢰 정책 제안 | 등록하지 않은 기기의 전송 요청을 거부함 |

아직 파일 크기 한도, 전송 속도, 발견 시간에 대한 수치 목표는 없다. 구현 전 대표 파일 크기와 실제 네트워크 환경을 기준으로 정한다.

## 5. 경계와 미결정 사항

- 같은 네트워크에서도 게스트 Wi-Fi, 기기 격리, 방화벽 때문에 통신이 차단될 수 있다. 자동 발견 실패와 실제 연결 실패를 구분해 안내해야 한다.
- 폴더 자체의 전송은 명시되지 않았다. 초기 설계는 일반 파일과 여러 파일 선택을 제안하며, 폴더 전송은 보류한다.
- 끊긴 전송의 이어받기와 자동 재시도는 미정이다. 초기 설계는 실패 표시와 사용자 재전송으로 단순화한다.
- Linux에 전달된 URL은 서버에서 자동 실행하지 않고 CLI로 읽는 방식을 제안한다.
- 초기 등록 방식, 기록 보존 정책, 자동 실행 기본값은 설계 단계에서 결정한다. 기술 스택은 후속 사용자 결정으로 Rust·TypeScript·Tauri 2로 확정했다.
