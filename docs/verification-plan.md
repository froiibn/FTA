# 설계 검증 계획

## 2026-11-06 확인된 네 가지 화면 경계 수정 검증

직전 점검의 네 문제만 수정했다. Mac·Windows CSS를 기본/최소 창에서 측정한 16개 경우(첨부 없음/25개 첨부, 긴 기록, 120바이트 등록 기기명)가 모두 통과했다. 작은 전송창에서는 본문을 내부 스크롤하면 전송/해제 버튼과 입력창이 창 안에 들어오고 제목 영역과 창 크기는 유지된다. 긴 기록은 텍스트 셀 안에서 줄바꿈되며 상태/삭제 버튼과 겹치지 않는다. 등록 기기명도 줄바꿈되어 해제 버튼이 수평 경계 안에 남는다. 두 플랫폼의 44×44 접힘/펼침 검사에서 토스트 숨김·타이머 해제·지난 결과 미재표시를 확인했다.

`npm --prefix apps/desktop run test:feedback` 15개(기존 기록/토스트 13개 + 접힘 회귀 2개), TypeScript/Vite 빌드와 Mac release 컴파일이 통과했다. 별도 식별자의 Mac 네이티브 검증 앱에서는 실제 파일 picker로 테스트 파일 하나를 선택하고 내부 스크롤로 버튼·입력창에 접근했다. 실제 Rust TLS로 저장한 긴 파일명/기기명이 기록·설정 버튼을 침범하지 않는 것도 확인했다. 실제 네이티브 위젯을 접은 뒤 격리 엔진만 종료해 연결 오류를 발생시켜도 위젯을 침범하지 않고, 펼쳐도 지난 토스트가 남지 않았다. 직전 점검에서 마치지 못한 Mac 파일 picker 경로도 이번에 확인했다.

색상·아이콘·소재·화면 순서·기본 크기는 유지했다. Windows는 공통 화면의 브라우저 렌더링 검증이며 네이티브 실행은 미검증이다. 증거는 `output/desktop-layout-fixes`에 보관한다. 사용자 설치 앱·공개 릴리스·태그는 변경하지 않았다.

## 2026-11-06 데스크톱 화면 틀 이탈 점검

사용자 요청으로 직전 토스트 수정이 포함된 로컬 소스를 점검했다. 화면 구성은 추가 변경하지 않았다. 실제 Rust 엔진 두 개가 TLS로 저장한 긴 파일명 25개·120줄 텍스트·긴 URL 및 허용 범위 내 120바이트 기기명을 사용했다. 온라인 기기는 실제 격리 엔진의 조회 결과이며 가상 온라인 기기를 제품 미리보기에 추가하지 않았다. 소스에서 만든 검사 전용 렌더링 어댑터로 Mac·Windows CSS의 기본/최소 크기, 설정 네 탭, 수신 세 종류와 접힘 상태를 브라우저에서 측정했다. 제품 호출·전송 상태는 변경하지 않았다.

발견 사항:

1. 전송창(280×260)에서 짧은 파일 하나를 선택해도 파일 동작 영역의 하단이 y=270, 메시지 입력창이 y=274..332에 배치돼 화면 밖으로 밀린다. 다수 파일에서는 동작 영역이 y=269..315, 입력창이 y=319..377이다. 고정 높이 flex 틀 안의 첨부 영역이 자체 최소 높이를 차지하고 shell overflow가 숨기는 조합이다. 240×230 최소 창에서는 첨부가 없어도 입력창 하단이 y=239로 일부 잘린다.
2. 기록 제목·기기명은 button의 `white-space: nowrap`을 상속해 `overflow-wrap: anywhere`가 줄바꿈을 만들지 못한다. 긴 글자가 상태·삭제 버튼을 침범하고 수평 스크롤을 만든다. Mac 기본 크기 네이티브 기록창에서도 재현했다.
3. 등록 기기의 공백 없는 긴 이름은 flex item의 자동 최소 너비 때문에 등록 해제 버튼을 화면 밖으로 민다. 너비 380에서 해제 버튼의 오른쪽은 Mac CSS 약923, Windows CSS 약841이다. Mac 기본 크기 네이티브 설정창에서도 재현했다.
4. 접힌 44×44 위젯은 `.shell`만 숨겨 body에 붙은 공통 토스트가 남는다. 토스트의 상단이 약 y=-13으로 잘려 위젯 그림을 침범한다. 직전 토스트 수정의 후속 보완 대상이다.

점검한 긴 URL·여러 수신 파일·긴 텍스트의 독립 상세 창, 설정의 기본 푸터·탭 배치는 내부 스크롤/화면 경계를 유지했다. 이는 검사한 데이터·크기에 한정하며 전송 중 모든 순간·모든 OS 글꼴을 검증한 것은 아니다. 파일 선택 경계와 접힘 토스트는 브라우저 렌더링 측정이며, Mac 네이티브 파일 선택은 자동화의 대화상자 확정 문제로 검증을 마치지 못했다. Windows 네이티브 실행은 미검증이다. 검사 결과·스크린샷은 `output/desktop-layout-audit`에 보관한다. 실제 설치 앱·공개 릴리스·태그는 변경하지 않았다.

## 1. 구현 전에 확인할 환경

Windows 대상은 사용자 확인으로 Windows 11·AMD Ryzen 5 5600X(x86-64)다. 맥 2대의 macOS 버전·CPU, Linux 배포판·CPU·libc·systemd 유무, LAN 대역과 게스트 격리 여부를 추가 확인한다. 각 기기의 기본 수신 경로와 여유 공간도 확인한다. 이 정보가 없으므로 최소 지원 버전과 빌드 조합은 아직 확정하지 않는다.

## 2. 호환성 검증 순서

1. OS별 작은 실행 파일로 트레이·메뉴 막대, 드롭, 로컬 알림과 클릭, 자동 실행, 키 보호를 검증한다.
2. Linux에서 GUI 없이 빌드·서비스 실행·SSH 종료 후 수신을 검증한다.
3. 동일 LAN의 실제 4대에서 발견·수동 연결·최초 등록·상호 인증을 검증한다.
4. 확정된 Rust·TypeScript·Tauri 2를 기준으로 키 접근 구조, 플러그인·라이브러리 버전과 프로토콜 구현을 고정한다. Tauri 알림 클릭·자동 실행·엔진 동봉, Windows WebView2와 macOS WKWebView의 동작 차이를 검증한다.

Linux 빌드는 Tauri·WebView·GUI 라이브러리를 설치하지 않은 환경에서도 CLI·엔진만 빌드되는지 확인한다.

이는 확정된 기술 스택의 OS별 통합을 검증하는 단계이며 전체 제품 구현의 완료를 의미하지 않는다.

## 3. 실제 기기 전송 행렬

네 기기를 W, M1, M2, L로 구분한다. 모든 방향 12개 조합을 검증한다.

| 송신 | 수신 |
|---|---|
| W | M1, M2, L |
| M1 | W, M2, L |
| M2 | W, M1, L |
| L | W, M1, M2 |

각 방향에서 일반 파일, 사진, 영상, 0바이트 파일, 한글·이모지 이름, 여러 파일, 줄바꿈 있는 텍스트, URL을 보낸다. 수신 승인 없이 지정 폴더에 저장되고 파일 SHA-256이 일치해야 한다. 데스크톱 수신은 알림→내용·위치 열기, Linux 수신은 CLI 조회를 검증한다.

| 알림 권한 없음·알림 클릭 시 앱 미실행 | 저장 유지, 기록 조회·내용 연결 가능 |
| 네트워크 전환·VPN 추가 | 허용되지 않은 인터페이스에 광고·수신하지 않음 |
| 접속 슬롯·텍스트 용량 초과 | BUSY·TOO_LARGE 등 계약된 오류 |
| 서버 로그아웃·재부팅 | 설정된 서비스 정책에 따른 수신, 상태 조회 가능 |
| 터미널 제어 문자가 담긴 메시지 | 기본 조회로 터미널 제어가 실행되지 않음 |

## 5. 비기능 검증과 추적

대표 영상 크기는 실제 사용 패턴 확인 후 정한다. 스트리밍 중 메모리가 파일 크기에 비례해 늘지 않는지, 진행률이 유지되는지 측정한다. 발견 시간과 전송 속도는 실제 네트워크에서 측정한 후 목표를 정하고 측정 전 성능 수치를 보장하지 않는다.

| 요구사항 | 검증 위치 |
|---|---|
| FR-01, FR-02 | 12방향 전송·오프라인·네트워크 전환 |
| FR-03, FR-04 | Windows·macOS 드롭·고정 패널 |
| FR-05 | 파일 종류·대용량·무결성·파일명 |
| FR-06 | 텍스트·URL·유니코드 |
| FR-07, FR-08 | 등록 후 자동 수신·폴더·충돌 |
| FR-09~FR-11 | OS 알림·내용·복사·링크 |
| FR-12 | Linux CLI·서비스·SSH 종료 |

문서 검증은 링크 정합성과 요구사항 추적을 대상으로 하며, 실제 구현·OS 권한·방화벽 동작 검증을 대체하지 않는다.

## 메시지 입력·이름 갱신·서비스 재시작 회귀 검증

- Mac 실제 앱에서 Shift+Enter 후 초안 유지·줄바꿈, Enter로 온라인 Windows에 전송·초안 비움, 성공 배너·완료 진행 상태·본체 스크롤 없음 확인.
- Mac 실제 앱의 재시작 버튼으로 기존 독립 엔진과 앱 소유 엔진을 재시작하고 새 PID·정상 IPC 상태·온라인 기기 복구 확인.
- 실제 TLS 테스트에서 이름 변경 후 같은 주소의 등록 기기를 조회해 새 이름·온라인 상태·저장된 이름 갱신을 확인하고 기존 인증서가 유지되는지 검증.
- 서브프로세스 테스트에서 독립 엔진을 IPC 정상 종료하고 잠금 해제·정상 프로세스 종료 확인.
- Mac에서 workspace 테스트·Clippy, 데스크톱 check/test/Clippy, fmt 검사, TypeScript/Vite 및 Mac 앱 번들 빌드 통과. Windows 네이티브 화면·새 엔진 배포 후 이름 표시는 미검증. 실제 한국어 IME 조합 입력은 미검증이며 이벤트의 조합 상태·229 키 코드는 전송하지 않게 처리.

## 등록 세션 복원 수동 검증 항목

- 대기·비교 중 설정 창을 닫고 다시 열어 같은 세션과 비교값·확인·취소 동작이 복원되는지 확인한다.
- 등록 모드·같은 미등록 기기를 반복 선택해 중복 세션 생성이나 중복 연결 없이 현재 등록을 이어가는지 확인한다.
- 다른 기기를 선택하면 현재 등록의 완료·취소 안내가 나오며 기존 비교값·확인 상태가 유지되는지 확인한다.
- 만료·취소 뒤 새 등록, 양쪽 비교값 일치 확인 뒤 등록 완료를 확인한다. Windows·macOS 실제 화면 및 양방향 등록 검증은 사용자가 직접 수행하며, 이 목록은 통과 기록이 아니다.
- 일반 기기는 먼저 발견됐지만 등록 광고가 늦거나 누락된 경우 등록용 광고를 제한 시간 내 재조회하는지 확인한다. 광고가 끝내 없으면 기록 삭제가 아닌 등록 주소 미발견 안내가 나오는지 확인한다.
- 설정 창을 연 채로 120초가 지난 뒤 대기 주소·비교값·확인 버튼이 초기화되고 새 등록 모드를 열 수 있는지 확인한다.

## 최초 전송 시 등록 확인 변경 (2026-10-28)

기본 전송은 감지된 컴퓨터 선택 → 최초 수신자 확인 → 같은 전송 계속 → 이후 즉시 전송으로 변경한다. 일반 MCP 전송은 등록 기기 한정이며, Linux의 명시적인 요청·승인 CLI와 데스크톱 네이티브 수신 확인은 [최초 전송 등록 설계](first-send-registration.md)를 따른다. 이전 실기 검증 기록은 이 변경의 검증을 의미하지 않는다.

## iOS 확장 검증 (2026-10-29)

iOS 빌드·시뮬레이터 UI와 실제 iPhone LAN 검증을 구분한다. 로컬 명령은 [iOS README](../apps/ios/README.md)를 따른다. 공통 코드를 바꾸면 기존 headless·Mac 데스크톱 검사도 실행하며 Windows·Linux를 실행하지 않았다면 통과로 보고하지 않는다.

실기기 행렬은 iPhone↔Windows/macOS/Linux, iPhone↔iPhone 각각 파일·텍스트·URL 양방향이다. Android는 해당 앱 구현 후 추가한다. 첫 전송 승인 전 payload 없음, 허용 후 완료, 등록 재사용, 거절·만료·취소·등록 해제·키 변경을 검사한다. 0바이트·대형·한글 파일, 동명 충돌·해시·공간 부족·공급자 입력·원본 변경·전송 중 잠금/홈 이동/앱 강제 종료·Wi-Fi 변경·완료 응답 유실을 포함한다. 파일 앱의 최종 파일과 비공개 partial 구분, 이동·삭제 후 기록, 알림 허용/거절·클릭·커서·재실행 복구도 확인한다.

기기 서명·설치·실행은 사용자 소유 Mac과 iPhone에서 진행한다. GitHub Actions는 추가·사용하지 않는다. 현재 수행 결과는 [iOS 문서](platforms/ios.md)에 기록한다.

## 온라인 목록 회귀 검사 (2026-10-29)

같은 ID의 주소·포트 변경 시 인증된 새 주소로 한 항목만 반환하는지, 이름이 같은 이전 오프라인 ID가 전송 목록에서 제외되는지 검사한다. 등록 기록은 삭제하지 않아야 한다. 미등록 광고는 살아 있는 소켓일 때만 후보로 남기며, goodbye 없이 리스너가 사라져도 다음 조회에서 제외돼야 한다. 이 확인으로 등록 세션·신뢰 저장이 생기면 실패다. iOS UI는 백그라운드 중지 후 대상·선택이 남지 않는지 확인하고, 실제 Wi-Fi 차단 및 원격 모바일 상실 실기는 별도로 구분한다.

## 모바일 미디어·단일 입력 검사 (2026-10-29)

`ContentRules.swift`를 직접 컴파일해 11개 메시지/URL 경계를 검사한다. 시뮬레이터 UI는 사진·파일 버튼 분리, 갤러리 로딩 완료·사진 선택·추가·비공개 준비 완료, 파일 초안 미변경, 텍스트/URL Picker 제거, 단일 입력·상태 점 화면을 확인한다. 시뮬레이터에 자체 앱 아이콘 PNG를 사진 fixture로 추가해 준비 파일의 SHA-256이 원본과 같은지 확인한다. 실제 iPhone 카메라 촬영·사진 송신은 별도로 구분한다. iPhone 업데이트는 기존 앱 삭제 없이 수행하고 앱 버전·프로세스·기기 ID 보존을 확인한다. PC는 TypeScript/Vite 빌드와 Mac 데스크톱 검사를 실행하며 Windows 실행과 PC 설치본 교체는 수행 범위를 구분한다.
