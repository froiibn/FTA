# Mac ↔ Windows 실제 LAN 파일 전송 검증

검증일: 2026-10-25 (Asia/Seoul). 실제 Mac과 Windows의 설치 엔진을 같은 집 LAN으로 연결했다. CLI → 사용자 전용 IPC → 엔진 → LAN TLS → 상대 엔진의 최종 저장을 검증했다. UI 클릭·드롭을 대신 검증한 것으로 해석하지 않는다.

## 환경과 준비

- Mac: macOS 26.6.2 arm64, 앱 번들에 동봉한 release 엔진 0.1.0과 로컬 CLI. 활성 인터페이스 두 개 중 Windows와 같은 대역의 유선 en0만 선택했다.
- Windows: Windows 11 x64 / Ryzen 5 5600X, 설치된 엔진 0.1.0과 CLI. Windows 플랫폼 수정본의 설치 상태는 Windows 에이전트가 확인했다.
- 양쪽 수신 주소와 허용 대역을 실제 집 LAN으로 설정했다. Mac 수신 폴더는 기존 Downloads/FTA를 유지했다. 임시 등록 주소에 연결해 양쪽 기기 ID와 비교값을 대조하고 양쪽에서 확정했다. 준비 중 만료된 세션은 사용하지 않았다.
- Windows 이더넷은 원래 Public이었다. 사용자가 직접 승인한 후 Private으로 변경했고, Windows 에이전트는 설치 엔진·Private·해당 이더넷·로컬 주소·집 LAN 대역의 TCP로 제한한 방화벽 규칙 한 개를 추가했다고 보고했다. Public 허용·전체 방화벽 해제는 하지 않았다. Mac 방화벽은 조회 당시 꺼져 있었고 이번 시험에서 변경하지 않았다.
- 테스트 전 등록 기기·기록·진행 중 전송은 없었다. 개인 파일 대신 각 OS에서 0바이트 파일, 한글·공백 이름의 72바이트 UTF-8 파일, 무작위 16MiB 파일을 생성했다.

## 확인된 결과

| 방향·시험 | 결과 | 전송 ID |
|---|---|---|
| Mac → Windows 3파일 | completed, Windows 실제 수신 파일의 크기·SHA-256이 Mac 원본과 일치 | `da134f8a-ccb8-4195-8a26-2246bfd382fb` |
| Mac → Windows 동일 3파일 재전송 | completed, `(1)` 이름으로 별도 저장; 기존·신규 6개 파일 해시 일치·원본 보존을 Windows 에이전트가 확인 | `4ab43e82-2243-4fe8-999a-dadffc66e05f` |
| Windows → Mac 3파일 | completed, Mac 실제 수신 파일의 크기·SHA-256이 Windows 원본과 일치 | `0ed0f315-fb2e-411d-bf63-61b6e195529e` |

| Windows → Mac 동일 3파일 재전송 | completed, Mac에서 기존·신규 6개 실제 파일의 크기·SHA-256 일치와 서로 다른 저장 이름을 직접 확인 | `50037bf2-02ed-4a71-8601-981cda88efa5` |

파일 body 응답이 아니라 수신 측 최종 commit이 확인된 결과를 사용했다. Mac 수신 파일은 부모 에이전트가 직접 읽어 SHA-256을 계산했고, Windows 수신 파일은 Windows 에이전트가 디스크에서 읽어 계산한 값을 Mac 원본 manifest와 대조했다.

## 증거와 남은 범위

로컬 `output/lan-test/`의 실행별 폴더에 원본 manifest, 전송 JSON, Mac 실제 수신 해시, 시험 전 Mac 설정과 결과 JSON을 보관한다. 테스트 파일과 기기별 설정·경로가 포함된 로컬 증거는 Git 추적에서 제외된다. 테스트용 수신 파일·등록 정보·LAN 설정은 임의 삭제하거나 loopback으로 되돌리지 않는다.

이번 통과 범위는 실제 양방향 파일 전송·최종 저장·0바이트·한글/공백 이름·16MiB·양쪽 수신 충돌 보존이다. 총 4회 전송·12개 항목을 검증했다. GUI 드롭, OS 알림 표시·클릭, mDNS 자동 발견, 대용량 영상·절전·중단 복구, 나머지 Mac·Linux 및 4대 12방향 전체 검증은 아직 통과로 표시하지 않는다. Windows는 발견을 끈 상태로 시험했다.
